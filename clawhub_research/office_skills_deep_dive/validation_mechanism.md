# 办公类 Skills 的“五维验证机制”与标准化流程

**作者**: Damon Li
**日期**: 2026-03-13

## 1. 验证背景

面对 ClawHub 上海量的 Skills，用户往往面临“用了才知道好不好”的困境。为了降低试错成本，本报告提出了一套标准化的“五维验证机制”，旨在通过客观指标评估 Skill 是否满足真实办公需求。

## 2. 五维验证指标体系

| 维度 | 指标名称 | 验证核心 | 满分标准 |
| :--- | :--- | :--- | :--- |
| **1. 准确度 (Accuracy)** | **指令理解率** | Skill 是否能准确识别自然语言中的参数（如：时间、地点、人物）。 | 10 次复杂指令测试，误识别率 < 10%。 |
| **2. 安全性 (Security)** | **权限最小化** | Skill 请求的 API 权限是否超出其功能范围，是否有数据外泄风险。 | 仅请求必要权限，支持本地沙箱运行。 |
| **3. 鲁棒性 (Robustness)** | **异常处理力** | 当 API 超时、网络波动或参数缺失时，Skill 是否能优雅报错或引导用户。 | 不崩溃，提供清晰的错误提示和重试建议。 |
| **4. 一致性 (Consistency)** | **多轮对话记忆** | 在连续对话中，Skill 是否能保持上下文一致，不丢失已确认的信息。 | 5 轮以上对话，上下文参数不丢失。 |
| **5. 效率 (Efficiency)** | **资源消耗比** | 执行 Skill 所需的 Token 数量及响应时间。 | 响应时间 < 3s，Token 消耗在合理范围内。 |

## 3. 标准化验证流程 (SOP)

### 3.1 准备阶段 (Preparation)
-   **环境隔离**: 在独立的 Docker 沙箱中安装待测 Skill。
-   **测试用例**: 准备 3 组测试数据（基础指令、复杂指令、异常指令）。

### 3.2 执行阶段 (Execution)
1.  **冒烟测试**: 执行最基础的功能（如：查询日历），验证 API 通讯是否正常。
2.  **压力测试**: 连续发送 5 条不同参数的指令，观察响应速度和准确度。
3.  **边界测试**: 输入缺失参数（如：只说“约个会”，不说时间），观察 Skill 的引导能力。

### 3.3 评估阶段 (Evaluation)
-   **日志分析**: 检查 `openclaw.log`，分析 Token 消耗和内部调用链。
-   **用户打分**: 基于上述五个维度进行 1-5 分的打分，计算加权总分。

## 4. 验证工具建议

建议开发一个轻量级的 **Skill-Tester** 脚本，自动模拟上述 SOP 流程，并生成可视化的验证报告。

## 5. 总结

通过“五维验证机制”，用户可以将感性的“好用”转化为理性的“达标”。这不仅有助于用户筛选 Skill，也为 Skill 开发者提供了明确的优化方向。
