# NanoClaw 深度调研报告：国产化替代与极简安全架构

## 1. 项目背景与定位
NanoClaw 是由 qwibitai 开发的极简 AI 智能体框架，旨在解决 OpenClaw 代码膨胀带来的审计难题。
- **核心代码量**：约 500 行 TypeScript（对比 OpenClaw 的数十万行）。
- **设计哲学**：物理隔离的极简主义。放弃复杂的权限检查，转而采用彻底的沙箱隔离。

## 2. 核心技术架构
- **隔离机制**：每个智能体运行在独立的 Docker 容器或 macOS Apple Container 中。
- **资源访问**：仅能访问被明确挂载（Mount）的目录，无法触及宿主机核心系统。
- **插件系统**：通信通道（Telegram, Discord 等）均为可选插件，按需添加。

## 3. 国产化适配分析 (针对电力内网)
- **运行环境**：Node.js 20+。
- **国产化潜力**：
    - **CPU/OS 适配**：由于基于 Node.js 和 Docker，理论上可以轻松适配鲲鹏/飞腾 CPU 以及麒麟/统信 OS。
    - **二开难度**：极低。500 行核心代码使得安全审计和功能定制非常容易。
    - **生态限制**：相比 OpenClaw，其原生 Skill 生态较小，需要手动配置和开发。
- **电力内网适用性**：非常适合作为内网高安全等级任务的执行引擎，尤其是需要严格物理隔离的场景。

## 4. 与 OpenClaw 的横向对比

| 维度 | OpenClaw | NanoClaw |
| :--- | :--- | :--- |
| **代码复杂度** | 极高 (数十万行) | 极低 (约 500 行) |
| **安全模型** | 逻辑权限控制 (易绕过) | 物理沙箱隔离 (强隔离) |
| **生态丰富度** | 极高 (数千个 Skill) | 较低 (需手动集成) |
| **部署难度** | 中等 (依赖较多) | 简单 (Docker 驱动) |
| **审计成本** | 极高 | 极低 |
