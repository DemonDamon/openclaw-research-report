# 南网 AI Agent 建设规划方案：可控、阉割、加固与功能增强

## 1. 核心建设理念：安全第一，功能受控

针对南方电网（以下简称“南网”）内网隔离环境的特殊性，直接部署原生的 OpenClaw 框架存在显著的安全风险。本方案提出“**核心保留、外围阉割、安全加固**”的建设理念，旨在构建一个既能发挥 AI Agent 自动化优势，又能严格遵守电力行业安全合规要求的企业级智能体平台。

## 2. “阉割与加固”方案：组件拆解与重构

为了确保 Agent 在内网环境下的安全运行，必须对开源组件进行深度定制。下表详细列出了针对南网环境的组件处理策略：

| 组件类别 | 处理策略 | 具体实施建议 |
| :--- | :--- | :--- |
| **外部连接** | **完全阉割** | 移除 Google/Bing Search 等公网搜索插件，切断所有指向公网的 Webhook 通知回调。 |
| **敏感指令** | **严格加固** | 默认禁用未审计的 `system.run` 指令，仅允许执行预定义的白名单脚本，并引入人工审批流。 |
| **数据安全** | **深度加固** | 引入敏感资产脱敏（Data Masking）模块，自动识别并过滤变电站 ID、电网拓扑等敏感信息。 |
| **执行环境** | **物理隔离** | 采用 Docker 或国产 iSulad 容器技术，为每个 Agent 提供独立的、无网络访问权限的运行沙箱。 |
| **生态系统** | **私有化重构** | 移除在线 Skill 商店，建设南网私有化 Skill 仓库，所有入库插件必须经过安全审计。 |

## 3. 核心功能建设：企业级 Cron 定时任务 (Cron-Claw)

在电力运维场景中，周期性任务占据了很大比例。因此，建设一个稳健的、可审计的定时任务系统（Cron-Claw）是南网 AI Agent 平台的关键功能。

> **设计目标**：参考腾讯元宝等主流产品的定时任务设置，但针对电力级可靠性进行增强，支持复杂的任务编排与失败告警机制。

### 3.1 Cron-Claw 核心功能规格

| 功能模块 | 规格说明 |
| :--- | :--- |
| **调度引擎** | 支持标准 Cron 表达式（如 `0 0 8 * * 1-5`），实现精确到秒级的任务触发。 |
| **任务编排** | 支持有向无环图（DAG）任务链，允许 A 任务成功后自动触发 B 任务执行。 |
| **容错机制** | 任务失败后支持自动重试（默认 3 次），并集成内网 OA/邮件告警通知。 |
| **环境隔离** | 每次定时任务均启动一个临时的、干净的容器环境，执行完毕后立即销毁。 |

### 3.2 典型应用场景

在实际运维中，Cron-Claw 可应用于**变电站日报汇总**（每天 8:00 自动调用监控 Skill 生成摘要）以及**负荷预测校核**（每小时自动抓取数据并对比预测模型偏差）等高频场景。

## 4. 南网 AI Agent 建设三步走规划

本方案建议采取分阶段实施的策略，逐步验证技术可行性并扩大应用范围：

1.  **第一阶段：单机沙箱试点 (POC)**
    重点验证 NanoClaw 或安全加固后的 OpenClaw 在内网环境下的基础运行能力。通过部署 1-2 个典型场景（如内网文档问答、简单脚本执行），形成初步的安全配置指南和资源消耗评估报告。

2.  **第二阶段：内网 Skill 平台建设 (Platform)**
    构建南网私有化的 Agent 基础设施，包括建设私有化 Skill 仓库、指令审计中枢以及企业级 Cron 调度系统。此阶段的目标是实现 Agent 的规模化部署，支持多部门间的协同作业。

3.  **第三阶段：全业务自动化协同 (Ecosystem)**
    使 AI Agent 深度融入南网核心业务流程，对接 SCADA、GIS、OA 等核心生产与管理系统。通过构建“数字员工”团队，实现跨系统的自动化运维，显著提升电网的整体运行效率。
