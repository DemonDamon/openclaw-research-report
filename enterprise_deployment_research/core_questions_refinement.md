# 电力内网 OpenClaw 部署核心调研问题提炼

针对客户提出的技术方案与资源需求，提炼出以下 6 个核心调研维度：

## 一、 技术方案深度解析

### Q1: 架构关系与核心优势 (OpenClaw vs Skill vs MCP)
- **调研重点**：OpenClaw 如何整合 Skill 和 MCP？在电力调度、设备巡检等场景下，OpenClaw 的“自主决策”相比传统“指令式 Skill”有哪些代差优势？

### Q2: 内网隔离环境下的能力边界 (Air-gapped Deployment)
- **调研重点**：在完全不连外网的电网内网，OpenClaw 的哪些核心组件（如：在线搜索、实时天气、外部 API 调用）会被阉割？如何通过“内网智搜”等本地化服务进行功能对冲？

### Q3: 内网生态构建与 Skill 迁移成本
- **调研重点**：外网丰富的 Skill 生态如何低成本迁移至内网？针对内网特有数据源（如：电网实时负荷、设备台账），Skill 的开发范式与外网有何不同？

### Q4: 国产化替代方案调研 (NanoClaw)
- **调研重点**：NanoClaw（港中文）在国产化适配（如：鲲鹏 CPU、麒麟 OS、昇腾 NPU）上的表现如何？其二开难度、文档完善度及与 OpenClaw 生态的兼容性分析。

## 二、 安全与资源保障

### Q5: 安全加固机制调研 (IronClaw & OpenClaw 3.11)
- **调研重点**：IronClaw 的核心加固逻辑（如：沙箱隔离、指令审计、敏感词过滤）。OpenClaw 2026.3.11 最新版在企业级安全（如：多租户隔离、RBAC 权限控制）上有哪些重大更新？

### Q6: 资源需求与 Token 成本优化
- **调研重点**：部署一套生产级 OpenClaw 需要多少通算（CPU/RAM）与智算（GPU/NPU）资源？针对电力场景下反复执行导致的 Token 消耗，有哪些缓存策略或模型蒸馏方案？
