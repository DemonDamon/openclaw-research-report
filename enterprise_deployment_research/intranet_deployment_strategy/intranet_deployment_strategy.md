# 电力内网隔离环境下的 OpenClaw 部署方案与资源规划

## 1. 内网隔离环境下的能力边界 (Air-gapped Boundary)
在完全不连外网的电网内网，OpenClaw 的核心能力将发生以下变化：
- **阉割功能**：实时网页搜索（Google/Bing）、外部社交平台集成（Slack/Discord）、公有云 API 调用、在线 Skill 商店自动更新。
- **对冲方案**：
    - **内网智搜**：对接企业内部知识库（RAG）或内网搜索引擎。
    - **本地模型**：部署 DeepSeek-V3 或 Llama-3 等国产/开源模型，替代 OpenAI/Claude。
    - **离线 Skill 库**：通过私有化 Skill 仓库进行分发和版本控制。

## 2. Skill 迁移与重构成本分析
- **迁移逻辑**：外网 Skill 大多依赖外部 API，内网部署需将 API 调用重定向至内网服务（如：内网邮件系统、OA 系统）。
- **开发范式**：内网 Skill 需深度适配电网特有协议（如：IEC 61850, DL/T 645），这部分工作量约占总开发量的 60%-70%。
- **规划建议**：优先迁移通用型 Skill（文档处理、代码生成），针对业务核心（负荷预测、故障诊断）进行定制化二开。

## 3. 资源需求规划 (Production-grade)
根据调研，生产级 OpenClaw 部署建议配置如下：

| 资源类型 | 基础配置 (仅 Gateway) | 生产配置 (含本地模型推理) |
| :--- | :--- | :--- |
| **通算 (CPU)** | 8 vCPU | 32-64 vCPU (推荐 AMD EPYC 或 鲲鹏) |
| **内存 (RAM)** | 16 GB | 128-256 GB (ECC 内存) |
| **智算 (GPU/NPU)** | 无需 | 2-4x NVIDIA A10/L40 或 昇腾 910B |
| **存储 (NVMe)** | 100 GB | 2 TB+ (用于模型权重与向量数据库) |

## 4. Token 消耗与成本优化策略
针对电力场景下反复执行导致的 Token 消耗，建议采取以下应对方法：
- **Prompt 缓存 (Prompt Caching)**：利用模型服务商或本地推理框架（如 vLLM）的缓存机制，减少重复系统提示词的计算。
- **会话压缩 (Session Compaction)**：定期对长对话进行摘要压缩，仅保留核心上下文。
- **模型分级调度**：简单任务（如格式转换）调用轻量级模型（如 Qwen-7B），复杂决策才调用旗舰模型。
- **离线批处理**：对于非实时任务，采用批处理模式以提高吞吐量并降低单位 Token 成本。
