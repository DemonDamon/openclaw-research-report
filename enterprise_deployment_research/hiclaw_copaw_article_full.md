## 一、轻量级 Worker

HiClaw 采用 Manager + Worker 的多 Agent 协作模式。社区反馈两大痛点：

1. 每个 OpenClaw Worker 容器占用约 500MB 内存，4-5 个 Worker 就需要 8GB+ 内存
2. Worker 跑在容器里，无法访问本地环境（浏览器、本地文件系统、桌面应用）

HiClaw V1.0.4 引入 CoPaw Worker 解决这两个问题。

## 二、CoPaw 核心特点

CoPaw 是基于 Python 的轻量级 AI Agent 开源项目：

- 轻量级：基于 Python，不需要 Node.js 全家桶，内存占用只有 OpenClaw Worker 的 1/5
- 控制台友好：内置 Web 控制台，管理频道、技能、定时任务、工作区文件、环境变量
- 执行速度快：Python 原生启动，冷启动时间短
- 扩展方便：基于 OpenAI SDK 的工具定义，上手成本低
- 记忆管理：内置 ReMe，对话自动压缩，重要信息持久保存

## 三、Manager-Worker 架构核心价值

### 传统方式痛点
- 需要逐个适配 Discord、Telegram、Slack、飞书、钉钉、微信、iMessage 等十几种渠道
- 每个渠道有不同的 API、认证方式、消息格式
- 用户需要逐个配置 webhook、token、证书

### HiClaw 解法：Matrix 作为统一通信层
- HiClaw 内置 Tuwunel Matrix Server（开箱即用）
- Worker 只需实现 Matrix Channel，即可复用所有 Channel 生态
- CoPaw 接入 HiClaw 核心代码只有两个文件：
  - matrix_channel.py (~450行)：实现 Matrix 协议通信
  - bridge.py (~230行)：桥接 openclaw.json 到 CoPaw 配置

### 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        HiClaw Manager                            │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │              Tuwunel Matrix Server (内置，开箱即用)       │  │
│   └─────────────────────────────────────────────────────────┘  │
│              ┌───────────────┼───────────────┐                 │
│              ↓               ↓               ↓                 │
│         Discord          Telegram         Slack               │
│         (通过桥接)        (通过桥接)       (通过桥接)            │
└─────────────────────────────────────────────────────────────────┘
                               ↑ Matrix 协议
┌──────────────────────────────┴─────────────────────────────────┐
│                        Worker                                   │
│   只需要实现 Matrix Channel —— 一个协议，搞定所有渠道           │
└─────────────────────────────────────────────────────────────────┘
```

## 四、两种部署模式

### 模式一：Docker 容器模式（更省内存）

| 对比项 | OpenClaw Worker | CoPaw Worker (Docker) |
|--------|----------------|----------------------|
| 基础镜像 | Node.js 全家桶 | Python 3.11-slim |
| 内存占用 | ~500MB | ~150MB |
| 启动速度 | 较慢 | 较快 |
| 安全性 | 容器隔离 | 容器隔离 |

### 模式二：本地模式（直接操作本地环境）

适用场景：
- 操作浏览器：自动化测试、网页截图、表单填写
- 访问本地文件：读取桌面上的文件、操作本地 IDE
- 运行桌面应用：自动化 Figma、Sketch、本地数据库客户端

CoPaw Worker 的本地模式直接运行在宿主机上，拥有完整的本地访问权限。
同时通过 Matrix 与 Manager 和其他 Worker 通信，融入 HiClaw 的多 Agent 协作体系。

### 混合部署架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     HiClaw Manager                               │
│                  (Docker 容器，管理所有 Worker)                   │
│                                                                 │
│   Worker A (OpenClaw)    Worker B (CoPaw Docker)                │
│   代码开发 / 数据分析     轻量任务 / 文档处理                    │
│   ~500MB                 ~150MB                                 │
└─────────────────────────────────────────────────────────────────┘
                               ↑ Matrix 协议
┌──────────────────────────────┴──────────────────────────────────┐
│                     你的本地电脑                                  │
│   Worker C (CoPaw 本地模式)                                     │
│   浏览器操作 / 本地文件访问                                      │
└─────────────────────────────────────────────────────────────────┘
```

## 九、写在最后

HiClaw 1.0.4 的核心目标是让 Worker 更轻、更灵活：
- 更轻：CoPaw Worker 内存占用大幅降低
- 更灵活：本地模式解锁了浏览器操作等新场景
- 更易接入：Manager-Worker 架构让新 Agent 运行时只需实现 Matrix 协议

推荐场景：
- 需要同时运行大量 Worker，但内存有限
- 需要操作本地环境的任务
- 想要可视化调试体验
